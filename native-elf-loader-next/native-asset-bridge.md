# Native asset bridge contract

Link native_asset_bridge.c and native-compat/assets.c with the JNI bridge, DVM and asset reader. Before starting guest native threads call native_asset_bridge_configure(vm, root), where root is the existing extracted APK assets directory (names passed to open are relative to this directory, without assets/). Configuration succeeds once; the VM, manager, root directory, and native threads must remain alive until process exit. No shutdown or VM replacement is supported; configure again fails. Files must stay immutable while open, especially while mapped. Missing files fail; extraction is the caller's responsibility.

The ELF resolver must prioritize native_asset_bridge_symbol for all AAsset and AAssetManager imports and must reject unknown AAsset* names instead of falling back to the system, so incompatible handle families cannot mix. JNI fromJava accepts only a current-thread bridge env and a valid local/global reference recognized by asset_reader_is_manager for the configured VM. Weak, foreign, deleted or other manager references fail. Individual wrapper handles are serialized under a mutex; closed handle tombstones are kept until process exit to reject stale handles without reuse. Returned buffer stays valid until close; callers must synchronize their buffer use with close. FD is a duplicated descriptor with offset zero and reported full length. Directory enumeration is explicitly unsupported (openDir returns NULL). No APK parsing, production teardown, or device validation is supplied.

Compile assets.c with -DGAME_ASSET_PRIVATE_BACKEND=1 for this bridge; the bridge source selects private names itself. Without this macro, the standalone native-compat library retains its existing public ABI. The global bridge mutex is held across file IO, so slow storage serializes asset operations and is a diagnostic performance limitation.
