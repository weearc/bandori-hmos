Exception handling path observed separately in 72fa/72fc requires java/lang/Object.toString `()Ljava/lang/String;` and Throwable virtual dispatch, rather than a direct query established in the bounded entry above. core-object-next/object_runtime.c implements Object.toString externally; 72fc JNI self-test found metadata missing, and a parallel change is addressing Object/Throwable metadata and virtual dispatch. No assumption is made that its fix is already in a tested binary.

Real capability limits: Class.forName implementation is limited to DVM-resolvable classes and the supported loader; it rejects custom loaders, so it is not a complete Android class-loading implementation. Class.getClassLoader identity is a runtime facade, not proof of Android platform loader behavior. Unity's downstream platform requirements, asset and display lifecycle remain separate unvalidated capabilities. The call at 0x9cba00 has multiple wrapper calls and string references; their signatures and receivers are unresolved and therefore excluded.
