# EGL window bridge: first-frame minimum plan

Status: source-only handoff plan. No code/device/build changes were made. Scope is the Unity window-surface boundary needed to attempt a first frame, not a complete Android graphics stack.

## Current contracts and evidence

- `window_runtime.h/.c` exposes only opaque generation-tagged 64-bit tokens. `acquire_current()` host callback returns an owned native pointer plus host generation; the runtime keeps one host ref per token and reference-counts token leases. `acquire_alive()` increments the token ref and validates the host generation via query. Queries/configuration pin `active_queries`; release changes the final slot to CLOSING and defers host unreference until those operations finish. There is no API to extract the native pointer or pin it across EGL calls.
- `probe.cpp` already has the actual host object path: XComponent Created/Changed obtains callback `void *window`, `AttachHostWindow` references it, stores `OHNativeWindow*` and increments `nativeWindowGeneration`; Destroy detaches/unreferences. `AcquireCurrentHostWindow` adds an owned OH reference and reports generation; query/configure compare pointer and generation under `nativeWindowLock`. Thus an appropriate host callback exists internally, but the currently installed `window_runtime_host` contract does not expose the native pointer to EGL code. `window_runtime_acquire_current()` returns only the opaque token.
- `surface-runtime-next` binds a trusted guest `android.view.Surface` to a window token and owns one token ref per binding. `surface_runtime_lookup_window()` returns that token; callers needing an outliving ref must use `window_runtime_acquire_alive()`. This is an identity/binding bridge, not an EGL native-window bridge.
- `unity-undefined-symbols.json` lists direct Unity imports for `eglGetDisplay`, `eglChooseConfig`, `eglGetConfigAttrib`, `eglCreateContext`, `eglCreateWindowSurface`, `eglDestroySurface`, `eglMakeCurrent`, `eglSwapBuffers`, `eglSwapInterval`, `eglQuerySurface`, `eglSurfaceAttrib`, and `eglGetProcAddress`. The direct import path therefore must be intercepted/remapped by the existing Unity ELF symbol resolver. A resolved host EGL `eglCreateWindowSurface` cannot receive a `window_runtime` token: it requires the real OH native window. Do not cast token to `OHNativeWindow*`.

## Smallest viable interface

Add a private `window_runtime` lease/pin operation that atomically validates a live token, pins the slot against final release/detach, and returns a borrowed `OHNativeWindow*` plus generation; pair it with an explicit unpin. Prefer a callback-shaped accessor in the runtime (`with_native_window(token, fn, user)`) if keeping the actual host pointer private is practical. The host `query` callback cannot supply it and must not be overloaded. Extend host ABI with an optional `acquire_native` returning an owned host reference, or add a separate host operation with matching release; do not expose an unowned pointer after dropping the runtime lock. `probe.cpp` can implement this from `currentNativeWindow` using `nativeWindowLock`, pointer/generation validation and `OH_NativeWindow_NativeObjectReference`.

Add an EGL bridge alongside the Unity symbol resolver, with a table keyed by guest `EGLSurface`: underlying OH EGLSurface, display, token/window generation, and owned native-window reference/pin. Route at minimum the listed imported EGL entry points through wrappers; translate guest surface handles on MakeCurrent/SwapBuffers/Destroy/QuerySurface/SurfaceAttrib as applicable. For CreateWindowSurface, resolve the Unity Android window token through the window registry, obtain a real OHNativeWindow lease, call platform EGL with that pointer, and only publish the guest EGLSurface mapping after successful creation. If Unity passes a different Android wrapper, its NDK shim must resolve that wrapper to its token first.

Suggested placement: keep host-window access/lifetime primitives in `native-window-next/window_runtime.{h,c}`; implement EGL handle translation in a new `native-window-next/egl_window_runtime.{h,c}` (or the loader's existing EGL override module if it owns symbol dispatch); wire wrappers where Unity imports are resolved, adjacent to the existing symbol binding table. Install host callbacks from probe initialization where `window_runtime_set_host` is already obtained (probe.cpp around the current dlsym at line ~1138). Do not make `surface-runtime-next` own EGL handles.

## Lifetime, destruction, failure

An EGLSurface owns a host-window lease independently of the Android wrapper/token's ordinary refs. On DestroySurface, call platform `eglDestroySurface` first; release its host lease/pin only once the platform surface no longer uses the native window. If destroy fails, retain the mapping and lease so retry/teardown remains safe. On XComponent Destroy or replacement, mark the generation unavailable, stop render/Unity use, destroy EGL surfaces while the display/context are still valid, then release leases and detach/unreference the host window. If platform destruction cannot run (lost display/context), retain/quarantine the lease until EGL teardown or process shutdown rather than unreference an in-use window. Never wait for EGL teardown while holding `nativeWindowLock` or the window runtime mutex.

Creation failures: invalid/stale token or generation => EGL_BAD_NATIVE_WINDOW; missing host bridge/native lease => fail without calling platform EGL; platform creation returns EGL_NO_SURFACE => release temporary lease and leave no mapping. Mapping allocation failure after platform creation => destroy the just-created platform surface, then release lease. Duplicate or unknown guest EGLSurface handles must fail deterministically; do not pass synthetic handles to platform EGL. Swap/MakeCurrent failures propagate platform result and do not silently retarget to the newest window generation.

## Dispatch coverage and limits

`eglGetProcAddress` is a bypass risk: Unity can obtain function pointers and call platform EGL directly, skipping import interposition. Wrap it so names covered by this bridge return bridge wrappers (at least CreateWindowSurface, DestroySurface, MakeCurrent, SwapBuffers, QuerySurface, SurfaceAttrib, SwapInterval); pass other names through. Also inspect Unity's dlsym/EGL loading path before claiming interception complete. A returned extension function can still accept/retain native-window or EGLSurface values; initially reject or pass through unsupported window/surface-affecting extensions explicitly rather than claim compatibility.

Initial bridge does not establish EGL config selection equivalence, full EGL extension semantics, Android BufferQueue/ANativeWindow ABI, Vulkan, protected/HDR surfaces, multi-window, robust context loss recovery, or a complete GLES feature set. `eglQuerySurface`/`eglSurfaceAttrib` need handle translation and attribute compatibility; extension entry points such as presentation time, damage regions, buffer age, native fence/sync, colorspace, frame timestamps, and Android native-fence APIs are unsupported until individually inventoried and bridged. A created EGLSurface or successful swap is not proof of a visible first frame; verify buffer submission and on-device presentation separately.

## Handoff sequence

1. Locate the Unity ELF resolver's exact import binding and add wrappers for the direct EGL imports listed above.
2. Add a generation-checked owned-native-window lease API; connect it to the existing probe host callbacks without token casts.
3. Implement guest EGLSurface mapping and creation/destruction pin ordering; integrate `eglGetProcAddress` interception.
4. Exercise null/stale window, changed generation, create failure, destroy failure, and concurrent detach paths before Unity initialization. Then attempt Unity init/surface and verify actual presentation on device.
